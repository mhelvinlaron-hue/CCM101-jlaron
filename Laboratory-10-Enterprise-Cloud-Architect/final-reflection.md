# Final Reflection: From Junior Trainee to Enterprise Cloud Architect

Across Laboratories 1 to 10, my view of cloud computing changed from "storing files online" to understanding how virtual machines, networking, databases, containers, automation, and security work together to form a working infrastructure.

The hardest concept was Docker and Docker Compose. Deploying WordPress and MySQL together showed me their purpose: WordPress runs the website, MySQL stores the data, and Compose manages both from one configuration file. I also learned that checking container status and reading logs is essential for troubleshooting. Setting up UFW with a default-deny policy reinforced a lesson from Laboratory 8: security should be built in from the start, since one wrong firewall step can lock out even the administrator.

What surprised me most in Laboratory 10 was the lack of step-by-step guidance. I had to read error messages carefully and solve problems on my own, including missing directories, GitHub commands, file paths, and service connections. These were frustrating, but they taught me that errors are part of learning.

For a real client, I would add HTTPS, strong passwords, protected database credentials, regular backups, and monitoring. For a larger business, I would consider a managed database, automated deployment, and infrastructure that scales with demand.

Overall, these laboratories made me more confident. Being an enterprise cloud architect is not only about commands and tools. It is about understanding user needs, solving problems, and designing systems that are secure, reliable, and practical.
